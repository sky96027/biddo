# 비즈니스 규칙 개요

중고 경매 시스템의 핵심 비즈니스 규칙을 정의합니다. 모든 개발자는 이 문서를 기준으로 로직을 구현합니다.

---

# 1. 입찰 규칙

## 최소 입찰 증가 단위 (현재가 비율 기반)

현재 입찰가에 따라 최소 입찰 증가량이 동적으로 결정됩니다.

| 현재 입찰가 범위 | 최소 증가 비율 | 예시 |
| --- | --- | --- |
| 0 ~ 9,999원 | 10% | 현재가 5,000원 → 최소 +500원 |
| 10,000 ~ 99,999원 | 5% | 현재가 50,000원 → 최소 +2,500원 |
| 100,000 ~ 999,999원 | 3% | 현재가 300,000원 → 최소 +9,000원 |
| 1,000,000원 이상 | 1% | 현재가 5,000,000원 → 최소 +50,000원 |

**규칙:**

- 최소 증가량은 100원 단위로 올림 처리합니다. (예: 2,500원 → 2,500원, 2,340원 → 2,400원)
- 입찰 금액은 반드시 `현재가 + 최소 증가량` 이상이어야 합니다.
- 철회 불가: 한번 입찰하면 취소할 수 없습니다.

## 본인 경매 입찰 금지

- 경매 등록자(판매자)는 본인이 등록한 경매에 입찰할 수 없습니다.
- 자동 입찰 설정도 불가합니다.

---

# 2. 자동 입찰 (Max Bid)

## 기본 동작

1. 사용자가 최대 입찰 금액(maxAmount)을 설정
2. 다른 사용자가 입찰하면, 시스템이 자동으로 최소 단위로 입찰
3. maxAmount에 도달하면 자동 입찰 중단 및 사용자에게 알림
4. 경매당 1인 1설정 (UNIQUE 제약)

## 충돌 처리 규칙

여러 자동 입찰가 동시에 트리거될 때:

| 우선순위 | 기준 | 설명 |
| --- | --- | --- |
| 1순위 | 금액 순 | maxAmount가 더 높은 사용자가 낙찰 |
| 2순위 | 선착순 | maxAmount가 같으면 먼저 설정한 사용자가 우선 |

**예시:**

- A가 maxAmount 100,000원 설정 (선착)
- B가 maxAmount 100,000원 설정 (후발)
- C가 80,000원 수동 입찰 시 → A가 자동으로 80,000 + 최소단위로 입찰 (선착순 우선)

# 3. 경매 종료 & 스나이핑 방지

## 경매 종료 기본 규칙

- 설정된 `end_time`에 도달하면 경매 종료.
- 종료 시점의 최고 입찰자가 낙찰자.
- 입찰이 없으면 유찰 처리.

## 유찰 처리 규칙

| 항목 | 규칙 |
| --- | --- |
| 유찰 조건 | end_time 도달 시 입찰 기록이 0건 (bid_count = 0) |
| 유찰 후 status | `ENDED` (별도 상태 없이 winner_id = NULL로 구분) |
| 알림 | 판매자에게 유찰 알림 발송 (AUCTION_END 알림에 유찰 명시) |
| 채팅방 | 생성하지 않음 (winner_id = NULL) |
| 재경매 | 새로운 경매로 등록 필요 (유찰된 경매 재활성화 불가) |

## 스나이핑 방지 (연장 규칙)

**경매 종료 10분 전 이후에 입찰이 발생하면, 경매 종료 시간을 10분 연장합니다.**

| 항목 | 값 |
| --- | --- |
| 연장 트리거 시점 | 경매 종료 10분 전부터 |
| 연장 시간 | 입찰 시점으로부터 +10분 |
| 최대 연장 횟수 | 제한 없음 |
| 연장 시 알림 | 네, 모든 참여자에게 COUNTDOWN_EXTENDED 이벤트 발송 |

**예시:**

- 경매 종료: 15:00
- 14:52에 입찰 발생 → 종료 시간 15:02로 연장
- 14:58에 또 입찰 → 종료 시간 15:08로 연장

# 4. 즉시 구매 (Buy Now)

## 기본 규칙

- 판매자가 경매 등록 시 `buy_now_price`를 설정할 수 있습니다 (선택).
- 즉시 구매가는 반드시 시작가보다 높아야 합니다.

## 즉시 구매 실행 시 처리

1. 즉시 구매자의 입찰을 `bid_type: BUY_NOW`로 기록
2. 경매 상태를 `SOLD`로 변경
3. 즉시 구매자를 `winner_id`로 설정
4. **진행 중이던 모든 자동 입찰을 비활성화** (`is_active: false`)
5. 경매 종료 알림 발송 (즉시 구매로 종료됨을 명시)
6. 낙찰 채팅방 자동 생성

---

# 5. 채팅 규칙

## 채팅방 생성

- 경매 낙찰 시 판매자-낙찰자 간 1:1 채팅방이 자동 생성됩니다.
- 시스템 메시지 자동 발송: 낙찰 안내 + 면책 고지 (상세 내용은 13조 "서비스 운영 목적 및 면책 고지" 참고)

## 채팅방 유효 기간

| 항목 | 값 |
| --- | --- |
| 유효 기간 | 낙찰일로부터 **2주일** |
| 만료 시 | 채팅방 상태를 `CLOSED`로 변경, 추가 메시지 불가 |
| 만료 알림 | 만료 1일 전 양쪽에게 알림 |

## 방 기능

- 텍스트 메시지 송수신
- 이미지 전송 (S3 Presigned URL 방식)
- 시스템 메시지 (낙찰 안내, 만료 예고 등)
- 읽음 확인

# 6. 후기 & 평판 규칙

> 후기 방향: **구매자 → 판매자 단방향** 으로 확정 (양방향 확장 없음)
>

> 수정/삭제 기한: 작성 기한과 동일하게 **낙찰 후 2주 이내**로 제한
>

## 거래 후기

| 항목 | 규칙 |
| --- | --- |
| 작성 자격 | 낙찰자 (구매자)만 작성 가능 |
| 작성 대상 | 판매자에게 작성 |
| 별점 범위 | 1~5점 (정수) |
| 작성 횟수 | 경매당 1회 (UNIQUE 제약) |
| 수정 | 가능 |
| 삭제 | 가능 |
| 작성 기한 | 채팅방 유효기간 내 (2주일) |

## 판매자 평판

| 항목 | 설명 |
| --- | --- |
| 평균 별점 | 해당 판매자의 모든 후기 평균 |
| 거래 완료 횟수 | 낙찰 후 후기가 작성된 건수 |
| 응답률 | 채팅방에서 첫 응답까지 평균 시간 |

## 신뢰도 점수

> 신뢰도 점수 산출 공식은 해당 기능 개발 시 상세 정의 예정.
>

고려 요소:

**[확정] trust_score 범위: 0.0 ~ 5.0점 / 업데이트: 배치 (일 1회 재계산) / 인간 가중치는 구현 시 확정**

고려 요소:

- 거래 후기 평균 별점 (가중 높음)
- 거래 완료율
- 응답 속도
- 가입 기간
- 신고 이력 (감점 요소)

# 7. 알림 규칙

> **[OUTBID 채널 역할 구분]**
>

> - **WebSocket `PRICE_UPDATE`**: 경매 페이지를 보고 있는 사용자에게 실시간으로 추월 사실을 반영 (페이지 접속 중 상태)
>

> - **SSE `OUTBID`**: 다른 탭에 있거나 페이지를 닫은 사용자에게 푸시 알림 (페이지 이탈 상태)
>

> → 두 채널이 역할이 중복되는 것이 아니라 서로 다른 상황을 커버하는 보완 관계입니다.
>

| 알림 유형 | 트리거 | 수신자 | 채널 |
| --- | --- | --- | --- |
| 입찰 발생 (BID) | 내 경매에 새 입찰 | 판매자 | SSE |
| 입찰 추월 (OUTBID) | 내 입찰가 추월됨 | 이전 최고 입찰자 | SSE |
| 경매 종료 (AUCTION_END) | 경매 시간 만료 | 전체 입찰 참여자 | SSE |
| 낙찰 (WON) | 경매 낙찰 | 낙찰자 + 판매자 | SSE |
| 가격 상승 (PRICE_ALERT) | 관심 경매 가격 급등 | 관심 등록자 | SSE |
| 채팅방 만료 예고 | 채팅방 만료 1일 전 | 양쪽 참여자 | SSE |
| 키워드 매치 (KEYWORD_MATCH) | 새 경매 등록 시 키워드/카테고리/가격 조건 일치 | 키워드 알림 구독자 | SSE |

# 8. 패널티 정책

## 낙찰 후 미거래

- 낙찰 후 2주일(채팅방 유효기간) 내에 거래가 완료되지 않으면, 상대방이 **신고** 가능.
- 신고 접수 시 해당 유저의 **평점에 패널티 반영** (신뢰도 점수 감소).
- 반복적인 미거래 신고 누적 시 관리자 검토 대상.

## 기타 금지 행위

- 가격 담합 (본인 경매에 다른 계정으로 입찰): 발각 시 경매 취소 및 계정 제재
- 허위 상품 등록: 신고 시 경매 삭제 및 계정 제재

# 9. 경매 수정 규칙

**수정 가능 조건:** `status: PENDING`(경매 시작 전)인 경우에만 수정 가능. 경매가 시작되면(`ACTIVE` 이후) 어떤 필드도 수정 불가.

| 항목 | 규칙 |
| --- | --- |
| 수정 가능 필드 | 제목, 설명, 카테고리, 상품 상태, 시작가, 즉시구매가, 종료시간, 이미지 전체 |
| 수정 불가 조건 | `status: ACTIVE` 이후 (경매 진행 중 / 종료 후 모두 불가) |
| 에러 처리 | 수정 시도 시 `409 Conflict` 반환 |

---

# 10. 경매 취소 규칙

**취소 가능 조건:** `status: PENDING`(경매 시작 전)인 경우에만 취소 가능. PENDING 상태에서는 입찰이 불가능하므로 "입찰이 없을 때만"과 동일 조건.

| 항목 | 규칙 |
| --- | --- |
| 취소 가능 조건 | `status: PENDING` |
| 취소 후 상태 | `status: CANCELLED` |
| 자동입찰 처리 | PENDING 상태에서는 입찰/자동입찰이 불가하므로 별도 처리 없음 |
| Kafka 이벤트 | `AUCTION_CANCELLED` 발행 → ES에서 해당 도큐먼트 삭제 또는 status 업데이트 |
| 에러 처리 | PENDING이 아닌 상태에서 취소 시도 시 `409 Conflict` 반환 |

# 12. 결제/정산 정책

> ⛔ **결제 기능 미구현** — 본 시스템은 결제/정산 기능을 구현하지 않습니다.
>

> **사유**: 포트폴리오 시연 목적의 서비스이며, 전자결제 중개 시 PG사 등록 등 법적 요건이 필요하므로 결제 기능은 제공하지 않습니다.
>

> 채팅방은 경매 기능의 기술적 시연을 위해 제공되며, 플랫폼은 사용자 간 실제 거래를 중개하지 않습니다 (13조 면책 고지 참고).
>

# 13. 서비스 운영 목적 및 면책 고지

## 운영 목적

본 플랫폼은 **개발자 포트폴리오 시연 목적**으로 제작된 프로젝트입니다. 상업적 이익을 추구하지 않으며, 수수료를 부과하거나 결제를 중개하지 않습니다.

## 면책 고지 (UI 표시 필수)

아래 내용을 서비스 내 다음 위치에 반드시 표시해야 합니다.

- 회원가입 시 이용약관 동의 화면
- 경매 등록 페이지 상단
- 입찰 페이지 상단
- 채팅방 상단 고정 시스템 메시지
- 서비스 푸터 (사업자 정보 영역)

### 면책 문구

> 본 플랫폼은 개발자 포트폴리오 시연 목적으로 운영되며, 실제 상거래를 중개하지 않습니다.
>

> 사용자 간 발생한 어떠한 거래, 금전 수수, 분쟁에 대해 플랫폼 운영자는 일체의 책임을 지지 않습니다.
>

> 본 서비스는 경매 기능의 기술적 구현을 시연하기 위한 목적으로만 제공됩니다.
>

### 이용약관 필수 포함 조항

회원가입 시 동의받는 이용약관에 아래 내용을 반드시 포함해야 합니다.

1. **서비스 성격**: 본 서비스는 개발 포트폴리오 시연 목적으로 운영되며, 상업적 거래 중개 플랫폼이 아닙니다.
2. **거래 책임 면제**: 플랫폼은 사용자 간 발생하는 거래, 금전 수수, 상품 하자, 사기, 분쟁 등에 대해 어떠한 책임도 지지 않습니다.
3. **실거래 금지 권고**: 본 서비스는 실제 물품 거래를 목적으로 하지 않으며, 사용자가 임의로 실거래를 진행하는 경우 그로 인한 모든 책임은 거래 당사자에게 있습니다.
4. **서비스 중단/종료**: 포트폴리오 목적의 서비스이므로 사전 공지 없이 서비스가 중단되거나 종료될 수 있으며, 이로 인한 손해에 대해 책임지지 않습니다.
5. **개인정보**: 수집된 개인정보는 서비스 이용 목적으로만 사용되며, 개인정보보호법에 따라 처리됩니다. 상세 내용은 개인정보 처리방침을 참고하십시오.

낙찰 후 채팅방 생성 시 자동 발송되는 시스템 메시지에 아래 내용을 포함합니다.

> ⚠️ 본 플랫폼은 개발 포트폴리오 시연 목적으로 운영됩니다.
>

> 실제 물품 거래를 중개하지 않으며, 사용자 간 발생한 거래에 대해 플랫폼은 어떠한 책임도 지지 않습니다.
>

## 개인정보 처리방침

서비스 내 별도 페이지로 개인정보 처리방침을 게시하며, 최소한 아래 내용을 포함합니다.

1. 수집하는 개인정보 항목 (이메일, 비밀번호, 닉네임)
2. 수집/이용 목적 (서비스 회원 식별 및 기능 제공)
3. 보유 기간 (회원 탈퇴 시 즉시 파기, 단 법령에 따른 보존 의무가 있는 경우 해당 기간까지)

6. 파기 절차 및 방법

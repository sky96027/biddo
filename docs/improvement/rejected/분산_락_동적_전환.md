# 분산 락 전략 동적 전환

> **상태**: 폐기
> **작성일**: 2025-06-19
> **폐기 사유**: 얻는 이점 대비 복잡도가 과도하며, 전환 경계에서의 정합성 리스크가 존재

---

## 현황

모든 입찰에 동일한 Redisson 분산 락을 적용 중.

## 문제 인식

경매별 트래픽 편차가 큼. 인기 경매는 락 경합이 빈번하지만, 비인기 경매는 락 오버헤드만 발생.

## 제안했던 방향

경매별 입찰 빈도(최근 N분 내 입찰 수)를 기준으로 락 전략을 분기한다. 경합이 적은 경매는 낙관적 락(버전 기반)으로 전환해 Redis 호출 비용을 줄이고, 경합이 많은 경매만 분산 락을 유지한다.

## 폐기 사유

### 1. 전환 타이밍의 정합성 리스크

비인기 경매가 갑자기 인기 경매로 전환되는 순간(바이럴, 종료 임박)이 존재한다. 낙관적 락에서 분산 락으로의 전환이 늦으면 동시 입찰로 데이터 정합성 문제가 발생할 수 있다.

- 낙관적 락 충돌 → 재시도 → 트래픽 증가 → 재시도 폭주
- 전환 기준인 "최근 N분 내 입찰 수"는 과거 데이터이므로 급격한 트래픽 변화를 반영하지 못함

### 2. 얻는 이점 대비 복잡도 과대

분산 락의 Redis 호출 비용은 1~2ms 수준이다. 비인기 경매에서 이를 절약하는 대신 다음 복잡도가 추가된다:

- 두 가지 락 전략의 병행 관리
- 전환 로직 및 임계값 튜닝
- 전환 경계에서의 엣지 케이스 처리
- 테스트 복잡도 증가 (두 전략 각각 + 전환 시나리오)

### 3. 선행 조건 미충족

현재 분산 락이 실제 병목인지 확인하는 메트릭이 없다. 측정 결과 병목이 아니면 개선 자체가 불필요하다.

## 대안

락 오버헤드가 실제로 문제가 되는 경우, 전략을 분기하는 대신 분산 락 자체를 경량화하는 방향이 더 단순하다:

- Redisson 락 대신 Redis `SET NX`로 간소화
- 경매 상태(종료 임박 여부)에 따른 락 타임아웃 조정

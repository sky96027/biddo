# 외부 의존성 장애 대응 (Graceful Degradation)

> **상태**: 부분 결정
> **작성일**: 2026-06-22
> **최종 수정**: 2026-06-24

---

## 현황

Elasticsearch에만 CircuitBreaker + DB fallback이 적용되어 있다. 나머지 외부 의존성(Redis, Kafka)에는 장애 시 대응 전략이 없다.

| 외부 시스템 | 장애 대응 | 영향 범위 |
| --- | --- | --- |
| Elasticsearch | CircuitBreaker + DB fallback | 검색, 유사 상품 추천 |
| Redis (Lettuce) | 없음 | 최근 검색어, 경매 상태 전환, Refresh Token |
| Redis (Redisson) | 없음 | 입찰 분산 락 — **입찰 기능 전체 불가** |
| Kafka 브로커 | 없음 | 입찰 이벤트 발행 — 알림/검색 동기화/WebSocket 전파 중단 |

## 결정된 사항

- **Redis 장애** → Sentinel 도입으로 SPOF 제거 + 자동 페일오버 결정. 잔여 과제는 페일오버 중 수 초간의 에러 처리. → [`accepted/Redis_Sentinel_도입.md`](accepted/Redis_Sentinel_도입.md)
- **Kafka 이벤트 유실** → Outbox 미도입, TransactionalEventListener 채택. at-most-once 수용. → [이슈 #42](https://github.com/sky96027/biddo/issues/42)

## 잔여 과제

### 1. Redis 페일오버 중 에러 처리

Sentinel이 페일오버하는 수 초 동안 요청이 실패할 수 있다. 연결 불가와 락 획득 실패를 구분하여 사용자에게 적절한 메시지를 제공해야 한다.

## 검증 계획

각 장애 시나리오의 실제 동작을 Testcontainers로 검증한다.

| 시나리오 | 검증 내용 |
| --- | --- |
| Redis 컨테이너 중지 → 복구 | 페일오버 중 에러 응답 확인, 복구 후 정상 동작 |
| Kafka 컨테이너 중지 → 복구 | 입찰 자체는 성공하는지 확인 |
| Elasticsearch 중지 → 복구 | 기존 CircuitBreaker + DB fallback 동작 확인 |
